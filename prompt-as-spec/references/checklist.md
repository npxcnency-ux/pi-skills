# Prompt 自检 Checklist

写完一份 prompt 后过一遍。打勾越多越稳。

---

## 一、决策前置（原则 1）

- [ ] 语言 / 运行时版本钉死（如 macOS 14+ / Node 20+ / Python 3.11）
- [ ] 框架 / 主要库钉死（如 Swift + SPM / Next.js 14 / FastAPI）
- [ ] 关键 API / 类名钉死（如 NSPanel(nonactivatingPanel) 而非"窗口"）
- [ ] 核心数据结构 schema 给出
- [ ] 架构形态明确（单文件 / 分层 / 状态机）

**自问**：LLM 还能在哪些点上做"主观选择"？想得到 → 没钉够。

---

## 二、可量化验收（原则 2）

- [ ] 所有尺寸都有具体数字（px / em / %）
- [ ] 所有时长都有具体数字（ms / s）
- [ ] 所有数量都有具体数字（5 根竖条而非"几根"）
- [ ] 所有阈值都有具体数字（超时 3s / 重试 2 次）
- [ ] 主观词（优雅 / 流畅 / 自然 / 合理）都被翻译成参数

**自问**：扫一遍 prompt，统计形容词数量。> 5 个 → 还有主观词没翻译。

---

## 三、反例约束（原则 3）

- [ ] 至少 3 条 "不要 XX" 约束
- [ ] LLM 最可能跑偏的点都加了反例
- [ ] 防止 "LLM 自作主张优化" 的约束（如 "不要重构无关代码"）
- [ ] 防止 "LLM 偷懒用假数据" 的约束（如 "波形必须由实时电平驱动"）

**自问**：闭眼想一遍 LLM 最可能怎么跑偏，每一种都补一句。

---

## 四、领域知识注入（原则 4）

- [ ] 平台陷阱显式点破（输入法、权限、事件链等）
- [ ] 反直觉决策都带了 why
- [ ] 关键转换 / 映射给了具体例子（如 "配森→Python"）
- [ ] 业务规则给了边界 case

**自问**：通用 LLM 不会知道的领域知识，是否都注入了？

---

## 五、交付契约（原则 5）

- [ ] 构建系统明确（Make / npm / SPM / Cargo）
- [ ] 入口点 / 启动命令明确
- [ ] 产物形态明确（CLI / app / library / Docker image）
- [ ] 运行模式明确（daemon / one-shot / interactive）
- [ ] 配置文件位置 / 格式明确
- [ ] 副作用复原契约（如恢复剪贴板、恢复输入法）

**自问**：LLM 写完，能直接 `make build && make run` 跑起来吗？

---

## 六、时序闭合（原则 6）

- [ ] 用户触发到结束的主流程串过一遍
- [ ] 异步操作的状态切换显式列出（如 "显示 Loading → 等返回 → 注入"）
- [ ] 分支条件显式列出（如 "如果 LLM 启用则 X，否则 Y"）
- [ ] 失败路径有兜底（超时、权限拒绝、API 失败）
- [ ] 副作用清理在 happy path 和 sad path 都覆盖

**自问**：闭眼走一遍用户使用流程，每个状态切换都覆盖了吗？

---

## 七、单 session 颗粒度

- [ ] 任务能在一个 LLM session 内跑完（无需中途压缩历史）
- [ ] 总代码量预估 < 1500 行（单 session 上限附近）
- [ ] 涉及文件数 < 10
- [ ] 没有跨大型现有代码库的依赖（否则上下文塞不下）

**如果超出**：拆成 3-4 个子任务，按 `spec-driven-dev` 的 Task 模板写。

---

## 最终自测

> 把这份 prompt 给两个不同的 LLM session 各跑一次，输出会**实质等价**吗？

- 等价 → ✅ 合格
- 部分等价（核心一致，边角不同）→ ⚠️ 边角处还有缝
- 完全不同 → ❌ 关键决策没钉死，回到原则 1
